# Kraken HTR cluster demo — Latin stone inscriptions

A small, self-contained **JupyterHub** use case for trying [Kraken](https://kraken.re)
HTR training on the cluster. You fine-tune a text-recognition model for Latin stone
inscriptions and compare four training recipes — in a few minutes on a GPU.

## Quickstart
1. Open this folder in **JupyterHub** (request a **GPU** session for speed; CPU works too, slower).
2. Open **`htr_cluster_demo.ipynb`** and run the cells top to bottom.

The notebook uses Kraken, fetches the base model, and trains — nothing else to set up.

## What's inside
- `htr_cluster_demo.ipynb` — the training walkthrough: setup → data → 4 recipes → comparison.
- `generate_inscriptions.ipynb` — generate synthetic data: run the generator → view → check GT alignment → inspect PAGE-XML.
- `make_synth.py` — self-contained generator for the synthetic stone data.
- `inscription_texts.txt` — **50,000** real EDH inscription texts (CC BY-SA 4.0, text only) the generator draws from.
- `fonts/` — **5** bundled Capitalis-style OFL fonts (Cinzel, Marcellus, Cardo, EB Garamond, Cormorant); the generator picks one per image, and it works offline.
- `stone_images/` — **16** real stone-texture patches used as backgrounds (with procedural stone as fallback).
- `data/real/`  — **50** annotated EDH inscriptions (image + PAGE-XML).
- `data/synth/` — **500** synthetic stone images (image + PAGE-XML).

Everything the notebook generates (compiled datasets, trained models) is written into
`arrows/`, `models/`, … and is git-ignored.

## Regenerate or extend the synthetic data
The synthetic stones are 100 % generated (so, unlike the photos, freely licensable).
The generator draws its texts from `inscription_texts.txt` (50,000 real EDH inscriptions,
CC BY-SA 4.0 — **text only, no photos**), so you can make tens of thousands of varied
images. Only Pillow + numpy needed; the five OFL fonts in `fonts/` are bundled, so it
works offline:

```bash
python make_synth.py --n 5000 --outdir data/synth --seed 42             # middot (·) between words (default)
python make_synth.py --n 5000 --outdir data/synth --seed 42 --no-dots   # scriptio continua
```

Middots are on by default because the real inscriptions in `data/real/` carry an
interpunct where the stone shows one, so the synthetic data matches that convention.
The output goes to `data/synth/`, which is exactly what `htr_cluster_demo.ipynb` trains
on. See `generate_inscriptions.ipynb` for a guided run.

It renders a weathered, carved inscription and writes **exact** PAGE-XML (baselines +
polygons) straight from the layout — no manual annotation. The full pipeline is in
`make_synth.py`:

- **stone** — a real texture patch from `stone_images/` (mirror-tiled), or procedural marble/limestone/sandstone if that folder is empty;
- **carve** — v-cut relief with directional lighting, fractal erosion, cracks and pits, plus *structural crossbar erosion* (the thin arms of T/E/F/L wear toward an I-stub while the label stays), the dominant real failure mode;
- **camera** — a global affine warp (rotation + shear), vignette, exposure and B&W-archive fading, sensor noise, blur, and JPEG compression.

The affine warp is applied to the PAGE coordinates too, so baselines and polygons stay
exact. Every `.ttf` in `fonts/` is used, one per image (seeded), so glyph style varies
without losing reproducibility. Drop in more OFL fonts (or more stone patches) to add
variety.

## The four recipes
Each fine-tunes the same base model and is **validated on real inscriptions only**
(synthetic data is used for training, never for scoring):

| recipe | training data |
|---|---|
| **real only** | 40 real |
| **pretrain → finetune** | pretrain on 500 synth, then finetune on 40 real |
| **mixed** | 40 real + 500 synth together |
| **weighted mixed** | 40 real ×5 + 500 synth |

Deliberately *plain & simple*: one train/val split, no cross-validation.
